1) Overview

The release includes two parts: nnstreamer plugin (modified), Ambarella gstreamer plugin.
The gstreamer part and gstd use yocto version.

gstreamer is an open source project, its focus is multimedia processing, its website is https://gstreamer.freedesktop.org/.
gstreamer is an open architecture, it provides a core framework named gstreamer-core, and also along with plenty of elements
 for multimedia processing, like gstreamer-plugin-base, gstreamer-plugin-good, gstreamer-plugin-bad, gstreamer-libav
 and gstreamer-rtsp-server.
 Writing plugin/element is an easy and typical way to extend gstreamer capability.
Ambarella Flexible Linux SDK support gstreamer 1.20.4 by yocto.

nnstreamer is an open source project, its focus is machine learning in gstreamer, its website is https://nnstreamer.ai/.
nnstreamer is gstreamer plugin, which includes a group of element for machine learning processing, especially for neural network
 inference. Ambarella's modification for nnstreamer is adding Ambarella neural network accelerator support. In Ambarella Flexible
 Linux SDK, the modified nnstreamer is based on nnstreamer version lts-2.0.1. Its location in SDK is ambarella/packages/mnnstreamer.

Ambarella gstreamer plugin inncludes elements for multimedia and machine learning related processing on Ambarella platform.
 Current version is 1.1. Its location in SDK is ambarella/packages/amba_gst_plugins.

gstreamer daemon, also called gstd, is a gstreamer framework for controlling audio and video streaming using an interProcess communication
 protocol. Its website is https://developer.ridgerun.com/wiki/index.php?title=GStreamer_Daemon.
Ambarella Flexible Linux SDK support gstreamer daemon by yocto.


Element list in Ambarella plugin:
  amba_camsrc: Amba Camera Source, output YUV frames
  amba_heicfilesink: Ambarella HEIC File Sink
  amba_hwvdec: amba hw video decoder
  amba_hwvdecsrc: Amba HW decode Source, output YUV frames
  amba_venccap: Amba Video Encoder, capture
  amba_vencdemux: Amba Video Encoder, demux
  amba_vsink: Amba Video Sink
  malsasrc: Audio source (ALSA)
  mlinference: Amba Machine Learning Inference
  amba_venc_overlay_bbox: Amba Venc Overlay for bounding boxes
  amba_overlay_src: Amba Overlay source, output clut and data for overlay
  amba_venc_overlay: Amba Venc Overlay, draw on overlay

Element list in nnstreamer plugin (based on lts-2.0.1)
  tensor_aggregator: TensorAggregator
  tensor_converter: TensorConverter
  tensor_crop: TensorCrop
  tensor_decoder: TensorDecoder
  tensor_demux: TensorDemux
  tensor_filter: TensorFilter
  tensor_if: TensorIf
  tensor_merge: TensorMerge
  tensor_mux: TensorMux
  tensor_query_client: TensorQueryClient
  tensor_query_serversink: TensorQueryServerSink
  tensor_query_serversrc: TensorQueryServerSrc
  tensor_rate: TensorRate
  tensor_reposink: TensorRepoSink
  tensor_reposrc: TensorRepoSrc
  tensor_sink: TensorSink
  tensor_sparse_dec: TensorSparseDec
  tensor_sparse_enc: TensorSparseEnc
  tensor_split: TensorSplit
  tensor_src_iio: TensorSrcIIO
  tensor_transform: TensorTransform

Element list in gstinterpipe plugin (based on v1.1.8)
  interpipesink: Sink for internal pipeline buffers communication
  interpipesrc: Source for internal pipeline buffers communication

a) Known issues:
  a.1) stuck in "amba_vencdemux" element when running with multichannel streams.
    For too many streams, it's needed to setup "alloc_mem=1" in "amba_venccap" element, "max-size-time=0 max-size-bytes=0 max-size-buffers=0" in "queue" element.
  a.2) stuck when playbacking (HW decoding) video and audio at the same time
    User can set the parameter "async=false" in the sink element.
  a.3) slices of frame dropped with gstinterpipe for multichannel streams.
    For h265 stream, it's random to drop some slices at start.

b) Notice:
  b.1) Starting GStreamer Daemon (default newer version)
    For newer version of gstd_0.15.0 in recipe-oss, simply run "gstd".
    For yocto community version of gstd(1.0+really0.8.0) in recipe-multimeida, run "gstd -D".
  b.2) Audio/Video synchronization
    User can set the parameter "sync=true" in "amba_venccap" element, default sync=true.
  b.3) Setup data formats of input tensors in tensor_filter's sub-plugin "amba_cvflow".
    Refered to the doc of CNNGen, setup the params[sign.datasize.exp_offset.exp_bits].
    If not set, refered to tensor types of input tensors, default _NNS_UINT8->[0.0.8.0]([0,2^(8-0)/2^8)), _NNS_FLOAT32->[1.2.0.7](IEEE-754)
